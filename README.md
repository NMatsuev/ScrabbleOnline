# Эрудит онлайн

Многопользовательский «Эрудит» в реальном времени: все игроки ходят одновременно, захватывают отрезки на общей доске и собирают слова. Работает в браузере на компьютере и телефоне.

- **Только JavaScript, без фреймворков и без внешних зависимостей.** Сервер — чистый Node.js, WebSocket-протокол (RFC 6455) написан вручную в `server/ws.js`; клиент — ванильный JS (ES-модули). `npm install` не нужен.
- **БД:** встроенный SQLite (`node:sqlite`, Node ≥ 22.5). Если его нет, автоматически включается JSON-файл с атомарной записью.

## Запуск

```bash
node server/index.js          # или: npm start
# открыть http://localhost:3000
```

Переменные окружения: `PORT` (3000), `DATA_DIR` (`./storage`, здесь лежит БД), `DICT_PATH` (`./data/dictionary.txt`).

Тесты: `npm test` (движок правил, WebSocket-сценарий «два игрока, конфликт, обрыв, перезапуск сервера», HTTP).

## Как играть

1. Введите имя, создайте комнату (длительность и число игроков) и отправьте друзьям ссылку или код.
2. Создатель нажимает «Начать игру». Первое слово из 5 букв появляется в центре само.
3. «Собрать слово» → нажмите первую и последнюю клетку отрезка (по горизонтали или вертикали, через хотя бы одну букву на доске) → ставьте буквы: на телефоне нажимайте буквы стойки, на компьютере можно печатать, перетаскивать, `Backspace` снимает, `Enter` подтверждает, `Esc` отменяет → «Подтвердить».
4. На сбор — 30 секунд, потом (после слова, отмены или тайм-аута) пауза 10 секунд. Обмен букв — вне сбора, пауза 15 секунд. Оставшиеся секунды всегда видны.
5. Побеждает первый, кто набрал нужное число очков. Оно показано на экране и зависит от режима и числа игроков.

| Режим | Доска | Очков для победы (2 / 3 / 4 игрока) | Лимит времени |
|---|---|---|---|
| Быстрая | 9×9 | 100 / 90 / 80 | 15 мин |
| Обычная | 13×13 | 200 / 180 / 160 | 30 мин |
| Долгая | 15×15 | 350 / 320 / 280 | 60 мин |

Лимит времени — страховка от «зависшей» партии: когда он вышел (или кончились буквы), побеждает лидер по очкам.

## Как выполнены требования

| № | Требование | Реализация |
|---|---|---|
| 1 | Мгновенная синхронизация через WebSockets | Любое действие уходит на сервер, сервер рассылает всем актуальное состояние в тот же такт. Чужие буквы видны в момент установки. |
| 2 | Только JavaScript без фреймворков | Node.js без пакетов, клиент на DOM API. |
| 3 | Сохранение данных между запусками | Состояние каждой комнаты (доска, мешок, стойки, захваты, таймеры) пишется в SQLite; при старте сервера комнаты и таймеры восстанавливаются. Итоги игр — в таблице `results`, последние показываются на стартовом экране. |
| 4 | Конкурентный доступ | См. раздел «Конфликты». |
| 5 | Потеря связи | Клиент переподключается сам, по токену возвращается на своё место, сервер присылает полное состояние. Подробнее ниже. |
| 6 | Развёртывание | См. раздел «Деплой». |

## Конфликты и их разрешение

Сервер — единственный источник истины. Node.js обрабатывает сообщения по одному, поэтому каждая команда атомарна, а при гонке выигрывает тот, чей запрос дошёл первым.

| Ситуация | Что происходит |
|---|---|
| Два игрока одновременно захватывают пересекающиеся отрезки | Первый запрос выигрывает. Второй получает сообщение «клетки заняты: …» и свежее состояние. |
| Отрезок цепляет клетку, где уже лежит буква другого отрезка | Клетки, входящие в чужой активный отрезок (в том числе с уже лежащими буквами), недоступны. |
| Отрезок не включает всю цепочку букв | Отклоняется: слово было бы длиннее выбранного. Проверяется при захвате и ещё раз при подтверждении, если рядом успели выложить букву. |
| Два игрока подтверждают соседние слова почти одновременно | Команды выстраиваются в очередь. Второе слово проверяется уже по обновлённой доске, включая побочные слова; если они стали недопустимыми, игрок получает ошибку и может исправить слово до конца времени. |
| Подтверждение и истечение времени в один момент | Решает серверное время: перед каждой командой применяются просроченные таймеры, действия после дедлайна отклоняются. |
| Один игрок открыл игру в двух вкладках | Оба соединения привязаны к одному месту и получают одно и то же состояние. |
| Повторная отправка команды после обрыва | Команды идемпотентны (поставить фишку в клетку, снять, отменить), а клиент после переподключения всё равно получает полное состояние. |
| Обмен при пустом/маленьком мешке, во время захвата, во время паузы | Отклоняется с понятным сообщением. |
| Игра закончилась, пока кто-то собирает слово | Все захваты отменяются, буквы возвращаются в стойки. |
| Бланк | Буква выбирается при установке; при снятии с доски бланк снова становится бланком; после подтверждения остаётся выбранной буквой и даёт 0 очков. |
| Одинаковое имя в комнате, переполненная комната, вход после старта | Отклоняется (вернуться в уже начатую игру может только владелец токена). |
| Игрок «пропал» | Его захват просто истекает по таймеру, остальные играют дальше. В лобби место освобождается через 5 минут без связи. |
| Перезапуск сервера | Комнаты и таймеры восстанавливаются из БД; игроки возвращаются по токену. |

## Потеря связи

- Клиент показывает баннер «Нет соединения», затемняет игровые элементы и блокирует действия; последнее состояние остаётся на экране и дублируется в `localStorage`, поэтому даже перезагрузка страницы без сети не теряет картину игры.
- Переподключение: экспоненциальная задержка до 8 секунд, мгновенно при событии `online` и при возврате на вкладку.
- Heartbeat: клиент шлёт ping каждые 8 с и считает связь мёртвой, если pong не пришёл за 5 с; сервер пингует каждые 20 с и отключает молчащие сокеты.
- Токен игрока хранится в `localStorage`; после обрыва, перезагрузки страницы или перезапуска сервера клиент входит обратно на своё место, и сервер присылает весь стол: доску, свой захват с уже поставленными буквами, стойку.
- Пока игрок offline, его захват продолжает тикать и по тайм-ауту очистится: игра в реальном времени не ставится на паузу.

## Принятые решения по правилам

- Слова считаются как в «Эрудите»: основное слово + все побочные слова, образованные новыми буквами в перпендикулярном направлении. Побочные слова тоже проверяются по словарю и дают очки.
- Премиальные клетки (×2/×3 буква, ×2/×3 слово) действуют только на новые буквы. Центр — ×2 слово.
- Бонус +15, если за один ход выложены все 7 букв стойки.
- Первое слово по центру выбирается случайно из словаря (5 букв, «лёгкие» буквы), его буквы берутся из общего мешка. Очков за него никто не получает.
- Набор фишек: 101 буква и 3 бланка (классическое распределение русской версии; «ё» играет как «е»). В словаре «ё» заменяется на «е».
- Мешок общий и ограниченный; после слова стойка добирается до 7. Если буквы кончились и у кого-то опустела стойка, игра заканчивается.
- Отрезок обязан содержать хотя бы одну букву, уже лежащую на доске, и хотя бы одну пустую клетку.
- Игроков в комнате от 2 до 4; после старта новые игроки не входят.

## Словарь

Встроенный `data/dictionary.txt` — стартовый список (около 2,9 тысячи самых употребимых существительных). **Для нормальной игры подключите полный словарь**, он подхватится без изменения кода:

```bash
# файл UTF-8, одно слово в строке (подойдёт любой список существительных)
node tools/build-dictionary.js путь/к/russian_nouns.txt
```

Скрипт объединит встроенный список с вашим файлом, приведёт слова к нижнему регистру, заменит «ё» на «е» и перезапишет `data/dictionary.txt`. Подходящие открытые списки: `Harrix/Russian-Nouns`, `danakt/russian-words` (последний в кодировке windows-1251, его нужно перекодировать в UTF-8). При сборке Docker-образа можно скачать словарь автоматически: `--build-arg DICT_URL=https://.../russian_nouns.txt`.

## Деплой

Нужен хостинг, который держит долгоживущий процесс и WebSocket (подойдёт любой VPS и большинство PaaS). Нужно, чтобы каталог `DATA_DIR` лежал на постоянном диске, иначе игры не переживут пересборку контейнера.

**Render** (`render.yaml` в репозитории): New → Blueprint → выбрать репозиторий. Постоянный диск доступен только на платных планах; на бесплатном плане всё работает, но БД стирается при перезапуске/простое.

**Fly.io** (`fly.toml`):
```bash
fly launch --no-deploy --copy-config
fly volumes create erudit_data --size 1
fly deploy
```

**Railway / любой хостинг с Docker:** собрать `Dockerfile`, смонтировать том в `/app/storage`, открыть порт из переменной `PORT`.

**VPS без Docker:** `git clone`, `node server/index.js` под systemd/pm2, перед ним nginx с проксированием WebSocket (`proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade";`).

Проверка после выкладки: `GET /healthz` возвращает `{"ok":true,...}`.

## Структура

```
server/
  index.js        HTTP (статика, /api/config, /api/results, /healthz) и WebSocket-апгрейд
  ws.js           WebSocket-сервер по RFC 6455 без зависимостей
  hub.js          комнаты, подключения, рассылка, таймеры, сохранение, восстановление
  engine.js       правила: захват отрезка, проверка слов, очки, обмен, конфликты
  config.js       константы: режимы, фишки, премиальные клетки, тайминги
  dictionary.js   загрузка словаря
  db.js           SQLite / JSON-хранилище
public/           клиент (index.html, style.css, js/app.js, js/net.js)
tools/            сборка словаря
test/             автотесты
```

## Протокол (кратко)

Клиент → сервер, JSON с полем `t` и необязательным `id`: `create`, `join`, `leave`, `kick`, `start`, `capture {x1,y1,x2,y2}`, `place {tileId,x,y,letter?}`, `unplace {x,y}`, `blank`, `commit`, `cancel`, `exchange {tileIds}`, `sync`, `ping`.
Сервер → клиент: `joined {room,token,pid}`, `state {now, game, you}` (полный снимок; стойка и предпросмотр слова — только в `you`), `ack {id, ok, code?, error?}`, `left`, `pong`.
